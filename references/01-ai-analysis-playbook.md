# AI 分析手册：把录屏变成"有叙事的教程"

## 0. 输入与心态
你拿到的是博主**边做边讲**的素材：顺序按操作发生，不按观众理解。你的工作是当**导演兼剪辑**：决定观众先看到什么、什么时候感到"哦原来如此"、什么时候爽。

## 1. 分析步骤（按序）
1. **承诺**：用一句话写 `观众能得到什么`（例：5 分钟内在 Mac 上跑起本地大模型）。这是全片的北极星，所有段落服务于它。
2. **画面×语音对齐**：转录告诉你"说了什么"，联系表告诉你"屏幕上是什么"。标注每段属于：
   `讲解(静止页)` / `操作(鼠标键盘在动)` / `等待(进度条/下载)` / `报错` / `结果展示`。
3. **宏观结构审查**（顺序 + 逻辑）——对照下面的"教程黄金结构"找问题。
4. **微观问题扫描**：重复、矛盾、失败、跑题、隐私、口误后更正。
5. **设计 Hook / 情绪曲线 / 章节**。
6. **布置 overlay**（B-roll、提示框、圈选、大字报、音效点）。
7. 写 `story_plan.json` → 校验 → 回头自查一遍"如果我是陌生观众，每 8 秒有新信息或新刺激吗？"

## 2. 教程黄金结构（宏观）
```
Hook(3-5s 结果/痛点冲击) → 承诺(10-20s: 做完你能…) → 前置准备 → 核心步骤 1…N(每步: 目标→操作→验证) → 常见坑 → 成果展示/对比 → 总结 → CTA
```
常见宏观问题与修法：
| 问题 | 修法 |
|---|---|
| 开头铺垫太长/先讲背景 | 把最终成果或最痛的问题前置做 Hook；背景压缩到 ≤15s |
| 结论/成果出现在最后才讲 | 抽 3-5s 成果画面做 `teaser_src`，结尾再完整演示 |
| 步骤顺序不符合依赖关系（先用后装） | 重排 segments；必要时用提示框补一句"先装好 X（下一步会讲）" |
| 同一主题分散在多处 | 合并到同一章，章内按"讲→做→验"排 |
| 补充说明/踩坑穿插在步骤中间打断流程 | 抽出做成"常见坑"章，或用 callout 短提示替代整段 |
| 结尾没有收束 | 加总结清单(checklist B-roll) + CTA |
> 重排后检查**指代**：被前移/后移的段落里若出现"刚才/上面/接下来"，要么重剪，要么用字幕/提示框弥补。

## 3. 微观问题（逐句扫）
- **重复**：同一句话说两遍 → 留语气更好的/信息更全的那遍。
- **前后矛盾**：以**最终正确**的说法为准，删掉被推翻的版本；若观众可能踩同一坑，反而保留并做成 `warning` B-roll。
- **失败重录**：保留最后一次成功；失败过程若有教学价值（典型报错）缩到 ≤5s + 红色 callout 解释原因。
- **跑题/闲聊/等待**：整段 drop，或操作类等待用加速（脚本自动处理）。
- **隐私**：密码、Token、邮箱、真名 → 不放入 segments，或用 `spot` 以外的方式遮盖（在 broll custom 里放模糊块）。
- **口误即时更正**（"这个是…不对，是…"）：只留更正后的部分，由 EDL 切点处理，必要时手动调整 segment 起点。

## 4. 宏观情绪曲线
观众的"想继续看"来自**张力的起伏**。用 Vonnegut 故事形状做骨架，教程里的映射：

| 形状 | 曲线 | 对应故事 | 教程用法 |
|---|---|---|---|
| **man_in_hole** 掉坑再爬出（默认） | 高→低→更高 | 《丑小鸭》式（被嫌弃→蜕变）、大多数"解决问题"教程 | Hook 展示成果(高) → 痛点/报错(低) → 逐步解决 → 成果升级(更高) |
| **cinderella** 灰姑娘 | 低→高→跌→大高 | 《狮子王》式（顺境→失去→成长→回归胜利） | 长教程：基础跑通(高) → 遇到进阶大坑(跌) → 高阶技巧逆袭(顶峰) |
| **rags_to_riches** | 稳步上升 | 清单/效率类 | 每章一个小爽点，递增 |
| **rise_fall_rise** | 先高后低再高 | 评测/避坑 | 先惊艳 → 暴露缺点 → 给出最优用法 |

落地：`emotion_curve.beats` 每章给 energy/valence，然后：
- **低谷章**：节奏放慢一点但不能拖；用 warn 大字报 + `error` 音效 + mascot 🤔，BGM 压低/换 tense。
- **爬升章**：每个小成功给 `chime`/打钩 checklist，镜头节奏加快。
- **高点章**：stat 数字冲击/mascot 🎉/sparkle 音效，BGM 抬 +3dB（`bgm.chapter_db`）。
- 最后一章必须是**全片最高点或最满足的收束**，再进 CTA。

## 5. Hook（前 3-5 秒）——完播率的生死线
公式（任选，headline ≤ 22 字）：
1. **结果前置**："3 分钟，让你的 Mac 跑起 ChatGPT 级模型"
2. **痛点直击**："还在手动配环境？你每周白白浪费 2 小时"
3. **反常识**："90% 的人装错了这一步"
4. **悬念/承诺**："看完这个，你再也不会被报错劝退"
5. **数字对比**："从 40 分钟到 40 秒"
执行：`teaser_src` 取最爽的 3-5s 画面 + 大字报 + impact 音效；第一句口播不要寒暄（"大家好我是…"全部砍/后移到 15s 后）。

## 6. 微观节奏（每 5-10 秒一个"新鲜点"）
- 一句话内不超过 0.5s 无意义停顿（EDL 自动处理）。
- 任何 **>5s 的平淡操作**：加速(自动) + 叠 `快进` 提示 + 一个情绪点（callout/stamp/音效）。
- **每 8 秒内**至少有一个：剪辑点 / 浮层 / 音效 / 画面变化。`09_finalize` 会报告空窗。
- 重要操作：先 `ring` 圈出 → 0.3s 后再让光标点击；关键结论用 `bignote` 强调。
- 信息密度高的段落：放慢，用 `step` 角标 + 字幕关键词高亮。
- 节奏型 B-roll：每 40-60s 一个，持续 3-6s，类型轮换（flow→compare→mascot→stat…），避免连续两个同类型。

## 7. 结尾引导
最后 4-6s：总结一句 + `cta`（点赞/关注/评论区聊聊 + 下期预告一句）。评论引导要具体（"你最常踩哪个坑？评论区告诉我"）。`extend:1.5` 冻结尾帧让 CTA 不压住最后一句话。

## 8. 自查清单（写完 plan 后）
- [ ] 一句话承诺能被开头 20s 清楚传达？
- [ ] 去掉任何一章，视频会不完整吗？（否则该章可删）
- [ ] 每章 ≥25s、≤2 分半？章节标题是"动词/名词短语"，不是"第一步"？
- [ ] 每 8 秒都有新刺激？B-roll ≥1/分钟？提示框 2-4/分钟？
- [ ] 所有 `src_t` 对应的画面真的在讲那件事（对照联系表）？
- [ ] 隐私信息已剔除？
